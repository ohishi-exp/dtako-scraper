# VDF (NET780) ドライブレコーダー映像ファイル フォーマット仕様

web地球号 (theearth-np.com) の「映像再生」ビューアで再生されるイベント映像ファイル
`*.vdf` のバイナリフォーマット解析結果。2026-07-02 に実ファイル
(`20260701_13472700382120260702_071029E.vdf`、車両3821 / 乗務員1556 / 急カーブ警告、
32秒クリップ) をリバースエンジニアリングし、ビューア表示値
(速度 25km/h・回転 1110rpm・G 前後-0.02/左右-0.01/上下1.03・GPS軌跡・イベント日時
07:10:52) との**完全一致を確認済み**。

リファレンス実装: [`scripts/vdf_extract.py`](../scripts/vdf_extract.py)
(前方/後方 MP4 + 速度/回転/Gセンサー/GPS の CSV を出力)。

関連: [`net780-binary-format.md`](./net780-binary-format.md) — 同じ NET780 機器が吐く
**運行単位の生データ ZIP** (.spd/.gpd/.rvd 等) の仕様。本ドキュメントはそれとは別系統の
**イベント映像ファイル (.vdf)** を扱う。

## ファイル名規約 (観測ベース)

```
20260701_134727 003821 20260702_071029 E .vdf
^運行開始?       ^車両   ^イベント映像開始  ^種別(E=イベント?)
```

## 全体構造

```
+0x000  ファイルヘッダ (NET780 マジック、下表)
+0x100  設定領域? (チャンネル構成らしき小さな struct 群、未解読)
+0x300  レコード列 (可変長、先頭1バイトで種別判定)
          fc = 映像フレーム / fd = テレメトリ / fe = イベント
末尾    ff レコード = シークインデックス (tick → ファイルオフセット対応表)
```

## ファイルヘッダ (offset 0x00〜)

| offset | 型 | 内容 | 実例 |
|---|---|---|---|
| 0x00 | char[8] | マジック `"NET780\0\0"` | |
| 0x08 | u16×4? | バージョン/フラグ (`01 00 5d 00 01 00 01 00`) | |
| 0x10 | u32 LE | 映像開始時刻 (UNIX秒、**JST の壁時計をそのまま epoch として格納**) | 1782976229 = 2026-07-02 07:10:29 |
| 0x14 | u32 | サブ秒? (`d0 01 01 00`) | |
| 0x18 | u32 LE | 映像終了時刻 | 07:11:01 |
| 0x20 | u64 LE | 開始 tick (デバイス起動からの ms カウンタ) | |
| 0x28 | u64 LE | 終了 tick | |
| 0x30 | u32 LE | 車両コード (数値) | 3821 |
| 0x34 | char[32] | 車両コード (ASCII) | `"3821"` |
| 0x50 | u32 LE | 乗務員コード (数値) | 1556 |
| 0x54 | char[32] | 乗務員コード (ASCII) | `"1556"` |

⚠️ **時刻は「JST をそのまま UNIX 秒に入れた」形式**。`utcfromtimestamp()` で
そのまま JST 表記になる。+9h してはいけない。

## `fc` レコード: 映像フレーム (40バイトヘッダ + H.264 ペイロード)

| offset | 型 | 内容 |
|---|---|---|
| +0 | u8 | マーカー `0xfc` |
| +1 | u8 | チャンネル: `0`=前方 (1280x720) / `1`=後方 (720x480) |
| +2 | u8 | 常に 0 or 1 (ch と連動、用途不明) |
| +3 | u8 | キーフレームフラグ (1=IDR、SPS/PPS 同梱) |
| +4 | u16 LE | 幅 (px) |
| +6 | u16 LE | 高さ (px) |
| +8 | u32 | 0 |
| +12 | u32 LE | ペイロードサイズ (バイト) |
| +16 | u32 LE | tick (ms) + u32 0 |
| +24 | u32 LE | タイムスタンプ (UNIX秒、JST) |
| +28 | u32 LE | サブ秒 (マイクロ秒) |
| +32 | u32 LE | tick 再掲 + u32 0 |
| +40 | bytes | H.264 Annex-B (`00 00 00 01` スタートコード区切り) |

- コーデック: H.264 Constrained Baseline。前方 SPS `67 42 40 1f ...` (Level 3.1)、
  後方 `67 42 40 1e ...` (Level 3.0)
- フレームレート: 前方 ≈9.2fps / 後方 ≈10fps (VFR。+24/+28 の実時刻を使うこと。
  **SPS 内 VUI のタイミング情報は嘘 (60fps 相当) なので ffmpeg に食わせると
  duration が 1/6 になる** — MP4 化はフレーム実時刻で mux する)
- 1秒 ≈ 1 GOP。キーフレーム毎に SPS/PPS が再送される
- 前方/後方フレームとテレメトリレコードがファイル内で時系列にインターリーブされる
- 音声トラックは無し (このファイルでは)

## `fd` レコード: テレメトリ (type 別固定長)

共通の末尾 16 バイト trailer: `ts(u32) + サブ秒µs(u32) + tick(u32) + 0(u32)`。

### `fd 00` Gセンサー (32バイト、10Hz)

| offset | 型 | 内容 |
|---|---|---|
| +2 | i16 LE | 前後 G (mG、1000=1.0G) |
| +4 | i16 LE | 左右 G (mG) |
| +6 | i16 LE | 上下 G (mG、静止時 ≈+1000) |
| +8 | 8B | 0 |
| +16 | 16B | trailer |

### `fd 01` GPS (40バイト、1Hz)

| offset | 型 | 内容 |
|---|---|---|
| +2 | u8 | 0 |
| +3 | char | fix ステータス (`'A'`=有効、NMEA 同様) |
| +4 | i32 LE | 緯度 ×1e7 (例 316049336 = 31.6049336°N) |
| +8 | i32 LE | 経度 ×1e7 |
| +12 | u16 LE | 不明 (観測値 0。速度 knots?) |
| +14 | u16 LE | 進行方位 (度、0-359) |
| +16 | 8B | 0 |
| +24 | 16B | trailer |

### `fd 02` 速度・エンジン回転 (32バイト、2Hz)

| offset | 型 | 内容 |
|---|---|---|
| +4 | u16 LE | 速度 ×0.01 km/h (例 2480 = 24.80 km/h) |
| +6 | u16 LE | エンジン回転数 rpm (例 1110) |
| +16 | 16B | trailer |

### `fd 03` sync/keepalive (24バイト)

payload 6 バイト (通常 0。イベント発生近傍で `00 00 00 01 00 00` を観測 —
イベントフラグ?) + trailer。フレームと同 tick で頻出。

## `fe` レコード: イベント発生マーカー (32バイト)

`fe 00 | 01 00 | fc 60 ea 00 | 04 ec 7f ae | b3 00 00 00 | trailer(16B)`

- trailer の ts がビューアの「映像日時」(= イベント発生時刻、例 07:10:52) と一致
- +2 の `01 00` はイベント種別コードと推定 (急カーブ=1?、他イベントのサンプル未取得)

## `ff` レコード: 末尾シークインデックス

`ff <len u16?> ...` に続き `(tick u32, file_offset u32, 0 u32)` の 12 バイト entry が
1秒 GOP ごとに並ぶ。再生シーク用。パース上は「ff に到達したら終端」で扱えばよい。

## 抽出のポイント

1. `0x300` から先頭バイトで dispatch: `fc`(40+size) / `fd`(type 別 24-40) /
   `fe`(32) / `ff`(終端)
2. 映像は ch 別に Annex-B を連結すればそのまま H.264 elementary stream。
   MP4 化は各フレームの ts+サブ秒 µs で VFR mux (リファレンス実装参照)
3. すべてのレコードが ts+µs を持つため、映像 ↔ テレメトリの時刻同期が可能

## Rust/WASM ビューアの実現性 (検討メモ)

**実現可能。** ポイントは「H.264 デコードを自前でやらない」こと:

```
[.vdf ArrayBuffer]
  └ wasm (Rust): VDF demux
       ├ 前方/後方 → fMP4 (moof/mdat fragment) に remux
       │    → JS: MediaSource Extensions (MSE) の SourceBuffer に append
       │    → <video> がブラウザ内蔵 HW デコーダで再生 (H.264 Baseline は全ブラウザ対応)
       └ テレメトリ (G/速度/回転/GPS/イベント) → serde-wasm-bindgen で JS へ
            ├ グラフ: Chart.js / canvas (video.currentTime と同期カーソル)
            └ 地図: Google Maps / Leaflet に polyline + 現在位置マーカー
```

- wasm 側の仕事は **バイナリの demux と fMP4 への箱詰め替えのみ** (デコード無し) なので
  軽量・高速。ffmpeg.wasm のような巨大依存は不要
- fMP4 remux は本ドキュメントの知見 + リファレンス実装の MP4 muxer と同等のロジック
  (数百行)。crate は `mp4` / 手書きどちらでも可
- フレーム単位のコマ送り・逆再生・canvas 合成が欲しくなったら WebCodecs
  (`VideoDecoder`) に差し替え可能 (Chrome/Edge/Safari 対応済み)
- Rust→WASM の前例はスタック内に既にある (ippoan/fc1200-wasm、wasm-pack)。
  Nuxt (nuxt-dtako-admin 等) のコンポーネントとして組み込む形が自然
