# NET780 デジタコ生データ バイナリフォーマット仕様

矢崎系デジタコ **NET780** が出力する運行単位の生データ (ZIP) のリバースエンジニアリング結果。
web地球号の CSV エクスポート (KUDG*.csv) とは別系統の、機器が直接吐くバイナリ形式。

- 検証サンプル: `27324455\4\2026\2131\20260702_095516-0-0-2131` (車両2131、2026/07/02、135.00km)
  および `27324455\1\2026\3899\20260701_060239-0-0-3899` (車両3899、2026/07/01、139.90km)
- 正解データ: 車両3899 (長崎100あ3899) 7/1 運行の運行記録計帳票 (速度・回転グラフ、開始 6:02 /
  終了 16:37、運転 4:20) と突合済み
- ステータス: **速度・距離・GPS・イベント/エラーは解読確定**。加速度は構造確定 (絶対スケールのみ未確定)

## ZIP 構造

```
<zip>
└── {車両CD}/
    └── {YYYYMMDD_HHMMSS}-0-0-{車両CD}/     # 運行開始日時
        ├── 080285762xx.fin                  # 0 byte マーカー (転送完了フラグと推定)
        ├── *.cfg   # 機器設定 (プレーンテキスト)
        ├── *.inf   # 運行メタデータ (CSV テキスト 1 行)
        ├── *.spd   # 速度データ (差分エンコード)
        ├── *.dsd   # 走行距離データ + オドメーター
        ├── *.gpd   # GPS データ
        ├── *.rvd   # 加速度 (G センサー) 波形
        ├── *.evd   # イベント / エラーログ
        └── *.tpd   # エンジン回転数 (推定、機器構成により無い場合あり)
```

## テキストファイル

### .inf — 運行メタデータ

カンマ区切り 1 行 (CRLF 終端)。フィールド:

| # | 例 | 意味 |
|---|---|---|
| 0 | `0001/01/01 12:00:00` | (固定値、未使用と推定) |
| 1 | `2026/07/01` | 運行日 |
| 2 | `0000003899` | 車両CD |
| 3 | `0000001270` | 乗務員CD |
| 4 | `2026/07/01 06:02:39` | 運行開始日時 |
| 5 | `2026/07/01 16:37:10` | 運行終了日時 |
| 6 | `139.90` | 走行距離 km |
| 7-9 | `000:00:00,000:00:00,0.00` | (未確定) |
| 12 | `6E72626E31536B3037540000` | 機種ID の hex 表現 (ASCII: `nrbn1Sk07T`) |
| 14 | `27324455\1\2026\3899\...` | サーバ側格納パス (comp_id 起点) |

### .cfg — 機器設定

`#` コメント付きの `KEY = VALUE` プレーンテキスト。冒頭に機種/ファーム情報
(`MachineID`, `Main App` 等)。注目キー:

- `BASE_VEHICLECD` — 車両CD
- `BASE_ANGLE_X / _Y / _Z` — **G センサー取付角** (.rvd の加速度を実 G に補正する際に必要)
- `# Pulse Settings` 以下 — 走行パルス係数

## バイナリ共通ヘッダ (全バイナリファイルの先頭 0x100 bytes)

.spd / .dsd / .gpd / .rvd / .evd / .tpd は全て同一レイアウトの 256 byte ヘッダを持つ。
数値は特記なき限り **BCD** (1 byte = 10進 2 桁)。

| offset | size | 内容 | 例 (車両3899) |
|---|---|---|---|
| 0x00 | 4 | マジック/バージョン `01 00 00 93` | |
| 0x04 | 10 | 機種ID (ASCII) | `nrbn1Sk07T` |
| 0x12 | 2 | 車両CD (BCD 4桁) | `38 99` → 3899 |
| 0x16 | 2 | 乗務員CD (BCD 4桁) | `12 70` → 1270 |
| 0x18 | 6 | 運行開始日時 (BCD YYMMDDhhmmss) | `26 07 01 06 02 39` |
| 0x1E | 6 | 運行終了日時 (BCD) | `26 07 01 16 37 10` |
| 0x24 | 6 | 開始時オドメーター (BCD 12桁、**0.1m 単位**) | `00 91 91 74 50 60` → 919,174,506.0 m |
| 0x2A | 6 | 終了時オドメーター (BCD 12桁、0.1m 単位) | 差分 = 1,399,050 dm = **139.905 km** (.inf の 139.90 と一致) |
| 0x3F | 3 | 日付 (BCD YYMMDD、運行日+30日 = 保持期限と推定) | `26 07 31` |
| 0x53 | ~6 | 個体差分 (シリアル/チェックサムと推定、未確定) | |

データ部は **offset 0x100** から始まる。

## 時刻表現 (バイナリデータ部共通)

u32 little-endian。**JST の壁時計をそのまま UNIX epoch として格納**した値
(= `datetime.utcfromtimestamp(v)` が JST 時刻になる。TZ シフト不要・厳禁)。

## .spd — 速度データ

可変長レコードの列。レコード:

```
ff ff | ts:u32le | f1:u16le | f2:u8 | samples:u8[]  (次の ff ff まで)
```

- サンプリング周期 **T = 0.5 秒** (全レコードで n×0.5 ≤ 次レコードまでの秒数、下限が 0.505 に収束することから確定)
- **sample = 前サンプルからの速度変化量。単位 0.1 km/h、127 = ±0** (符号付きオフセット)
- レコード先頭からの累積和 `Σ(sample - 127)` × 0.1 = その時点の速度 km/h
- レコード = 概ね「走行区間」。レコード間ギャップ = 停車/エンジン停止
- f1 / f2 の意味は未確定 (f1 は 0-88 程度の小さい値)

**検証**: 全レコードの速度を時間積分した走行距離 = 134.6 km vs 実距離 139.90 km
(誤差 4% は累積和ドリフト。距離の正は .dsd を使い、.spd は波形形状に使う)。
GPS 実測区間で .dsd 由来速度 (50.4 km/h) と .spd 積算速度 (47〜49 km/h) が相互一致。
復元した速度波形は運行記録計帳票のグラフと走行ブロック・巡航速度 (40〜60 km/h) が一致。

注意: 累積和は負に振れ得る (ドリフト、レコード末尾で -10 程度)。実装では 0 で clamp する。

## .dsd — 走行距離データ

```
ff ff | ts:u32le | odometer:u32le | samples:u8[]
```

- odometer: 車両積算距離 **メートル単位** (ヘッダ BCD オドメーターの 1/10 値と一致)
- sample = **0.5 秒間の走行距離 (m)** (整数、0〜9 程度)
- **全サンプルの総和 = 139,921 m = .inf の 139.90 km と完全一致** (最重要の検証結果)
- 瞬間速度 = sample × 7.2 km/h (分解能 7.2 km/h — 粗い。精密な速度は .spd と併用)
- レコードは .spd と同一時刻・ほぼ同一サンプル数 (dsd が +1 になる傾向、先頭 1 byte の扱い要確認)
- per-record では `Σsamples` と odometer 差分が ±1 ずれることがある (丸め)。総和は一致する

## .gpd — GPS データ

**16 byte 固定長**レコード:

```
ff ff | ts:u32le | lat:u32le | lon:u32le | b14:u8 | b15:u8
```

- lat / lon = **度 × 10⁶** (WGS84 と推定)
- 記録間隔: 基本 60 秒 + 運行開始/停車時に 1 秒間隔バースト
- b14 / b15: 未確定 (b15 は 0-255 で変動 — 方位 (×256/360°) の可能性)

**検証**: 座標は長崎県沿岸部の実在走行域、軌跡積算距離は実距離と整合 (疎サンプリング分の過小のみ)。

## .rvd — 加速度 (G センサー) 波形

.spd と同一のレコード構造 (`ff ff | ts | f1:u16 | f2:u8 | samples`)。

- sample = 加速度。**127 = 0 中心の符号付きオフセット**、通常走行で ±40 カウント程度のスパイク
- サンプリング 0.5 秒、**停車中 (エンジン ON) も記録が継続する** (.spd は走行時のみ)
- 絶対スケール未確定 (0.01 G/count と推定。急ブレーキ等の既知イベントで要校正)
- 実 G への変換には .cfg の取付角 (`BASE_ANGLE_X/Y/Z`) 補正が必要
- 軸数は未確定 (1 軸=前後 G と推定。多軸インターリーブの可能性は要追加検証)

## .evd — イベント / エラーログ

可変長レコード (マーカー無し、詰めて格納):

```
ts:u32le | flags:u16le | code:u8 | subcode:u8 | len:u8 | payload[len]
```

検証サンプルでは 4,248 byte / 315 イベントが 1 byte の余りなくパース可能 (構造確定)。

### 判明しているイベントコード

| code | 内容 |
|---|---|
| 0xA0-0xAB | 定常イベント (運行開始/状態遷移ハートビート系) |
| 0x11/12/16/17/21/22/26/27 | 作業状態 ON/OFF (荷積・荷降ボタン等と推定、payload 1 byte = 0/1) |
| 0xB8 / 0xB9 | 通信断 / 復帰 (payload u32 = 対象時刻) |
| 0xC1 | サーバ交信プロトコルログ (payload に ASCII: `CRC OK` `CWC OK` `LS Y/N` `US` `ET A` 等) |
| 0xD2 | 運行終了サマリ (ASCII CSV: 例 `4,1,0,4,2,1,4,3,054.00`) |
| 0xFB / 0xFC | 起動時情報 |
| **0xFE** | **診断 / エラーログ**。subcode 別 (下表) |

### 0xFE subcode (通信モジュール診断)

| sub | payload | 内容 |
|---|---|---|
| 0x05/0x06/0x07 | バイナリ | リトライカウンタ類 |
| 0x0A | ASCII | **AT コマンドログ / エラー** (実例: `AT^SWWAN=1,1,1` → `+CME ERROR: unspecified GPRS error`) |
| 0x0E | 1 byte | モデム状態 |
| 0x0F | ASCII | デバイスパス (実例: `dev/ttyACM0` — モデム再初期化) |

## .tpd — エンジン回転数 (推定)

20 byte 固定長・60 秒間隔レコード (車両2131 のみ存在、3899 には無し):

```
ts:u32le | v1,v2,v3:u16le ×3 | u16 | v4,v5,v6:u16le ×3 | u16
```

値はアイドル時 678〜750 → **rpm の min/avg/max ×2 系統**と推定。未検証
(正解データ側の rpm グラフとの突合が必要)。

## Rust 実装方針

- 本 repo (dtako-scraper) に `src/net780/` モジュールとして実装
  (`header.rs` / `spd.rs` / `dsd.rs` / `gpd.rs` / `evd.rs` / `inf.rs`)
- pure 関数中心 (bytes in → struct out)、ファイル I/O と分離してユニットテスト可能にする
  (rust-alc-api の「外部 API 連携の開発フロー」と同じ方針)
- 検証済みサンプル ZIP から抜いた小さな fixture (ヘッダ + 数レコード) を `tests/fixtures/` に置き、
  本仕様書の検証値 (距離総和 = .inf 距離、ヘッダ BCD = .inf 値) をテストで固定する
- 速度時系列の出力は .dsd (距離の正) + .spd (0.1 km/h 分解能の形状) の併用で生成する
